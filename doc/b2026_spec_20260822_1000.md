# B2026: A B1700-Inspired Soft Machine for the Tang Nano 9K

Version: v0.6 (2026-08-22)
Author: Senol Gulgonul
Status: draft for discussion. Project name is provisional.

## 1. Design thesis

B2026 is a microprogrammed "soft machine" in the tradition of the Burroughs
B1700 (Wilner, AFIPS FJCC 1972). The hardware defines no instruction set
architecture. It provides a small single-cycle micromachine, a defined-field
memory interface, and a writable control store. Target ISAs (S-languages, in
Wilner's terminology) are implemented as interpreters written in microcode.
The first S-language is RV32I.

Five principles carried over from Wilner:

1. Defined-field access. Memory is addressed by (bit address, length,
   direction) descriptors. A Field Isolation Unit (FIU) in front of
   conventional BSRAM performs extraction and read-modify-write insertion,
   exactly as the original FIU sat in front of conventional core memory.
2. Bias registers. CPL (current operand length, 1 to 32) reshapes the ALU
   every cycle: carry position, zero and sign detection, and masking all
   follow CPL. CPU (unit type) is reserved; v0.1 is binary only.
3. Microcode is software. The control store is writable at run time over
   UART. Interpreter switching is a microcode routine (the Gismo analog),
   not a hardware mode.
4. S-machine state lives in memory. The interpreted machine's registers
   (for RV32I, x0 to x31 and pc) are fields in S-memory, not hardware
   registers. Any interpreter can be suspended between two S-instructions
   with no hidden processor state.
5. Readable microassembly. The microassembler (MILce, a browser-based
   single-file tool) uses imperative one-line statements, one statement per
   microinstruction, in the spirit of Burroughs MIL.

Deviations from the B1700, chosen deliberately: 32-bit datapath instead of
24-bit; field length limited to 32 bits per access (longer fields by
iteration, as on the B1700 itself via Bias and Count); no BCD arithmetic in
v0.1; separate control store BSRAM in v0.1 instead of executing microcode
from main memory (unified memory with M-cache is a v2 fidelity goal).

## 2. Target platform and budget

Tang Nano 9K, Gowin GW1NR-9: 8640 LUT4, 6480 FF, 468 Kbit BSRAM (26 blocks
of 18 Kbit), 27 MHz crystal.

Budget targets:
- Control store: 1 BSRAM block, 1024 x 16 microinstructions in v0.1
  (expandable to 4K x 16 with 4 blocks). Wilner's profile data (1000 micros
  cover over 99 percent of executed micros) motivates the 1K starting size.
- S-memory: 20 blocks, 45 KB, organized 32 bits wide for the FIU.
- Logic: 2000 to 2800 LUT estimated (FIU funnel ~400 to 600, function box
  ~250 to 350, sequencer and decode ~300, scratchpad and muxing ~300,
  UART and loader ~200, margin for the rest).
- Clock: 27 MHz, every microinstruction single cycle except memory
  READ/WRITE which may take 2 to 3 cycles (read-modify-write).

## 3. Programmer-visible micromachine state

- S0..S15: sixteen 32-bit scratchpad registers (LUT RAM).
- X, Y: 32-bit operand registers feeding the function box.
- Function box outputs, read-only pseudo-registers recomputed every cycle
  from X, Y, CPL: SUM, DIFF, ANDR, ORR, XORR, MSKX (X masked to CPL bits).
  This mirrors the B1700's 24-bit function box: you do not "execute an add",
  you read SUM when you want it.
- T: 32-bit transfer register, target of LIT and EXT.
- F and SF: field descriptors. Each is FA (24-bit bit address), FL (16-bit
  length), FD (direction bit). Subfields individually addressable as
  registers (F.A, F.L, SF.A, SF.L).
- CPL: 6-bit effective operand length, 1..32.
- MPC: 12-bit micro program counter. MSTK: 16-deep hardware microstack.
- Flags, all biased by CPL: CYL (carry out of bit CPL-1), Z (masked zero),
  N (bit CPL-1 of SUM), and FL0 (F.L == 0), SFL0 (SF.L == 0).

Register namespace is 6 bits wide (64 names) covering S0..S15, X, Y, T,
function outputs, descriptor subfields, CPL, UART data/status, and reserved
slots.

## 4. Microinstruction format, 16 bits, vertical

Class in bits [15:12]:

- 0 MOVE  src6 -> dst6            [11:6] src, [5:0] dst
- 1 LIT   T <- zext(imm12)        [11:0] literal
- 2 LITS  T <- (T << 12) | imm12  [11:0] literal (32-bit constants in 3 micros)
- 3 READ  reg4 <- field           [11:8] dest, [7] F/SF select,
                                  [6:5] count mode (none; A up L down;
                                  A down L down; A up only),
                                  [4:0] length: 0 means CPL, else literal 1..31
- 4 WRITE field <- reg4           mirror of READ
- 5 EXT   T <- (X >> pos) & mask(CPL)   [11:6] pos 0..31, [5:0] reserved
- 6 BR    MPC <- MPC + simm12     [11:0]
- 7 IF    if cond then MPC += simm8   [11:8] cond, [7:0] simm8
          conds: Z, NZ, CYL, NCYL, N, NN, FL0, FLNZ, SFL0, SFLNZ, INT, TRUE
- 8 CALL  push MPC+1; MPC <- target   [11:0] absolute low 12
- 9 EXIT  MPC <- pop               (subops in [11:0]: EXIT, EXITC cond)
- A DISP  MPC <- {page[3:0], T[7:0]}  [11:8] page. Dispatch table jump for
          S-op decode. One micro from extracted opcode to handler.
- B BIAS  CPL <- source            [11:0]: literal 1..32, or F.L, SF.L,
          or min(F.L, 32) variants
- C CNT   count descriptors        F.A +- k, F.L -+ k where k is CPL or
          literal, encoded in [11:0] (the Count F analog)
- D..E    reserved (BCD/CPU bias, multiply step, candidates for v2)
- F CTRL  sub 0 NOP, sub 1 HALT, sub 2 MONITOR imm8, sub 3 MONR
          (monitor <- T), sub 4 URXACK (consume the received byte),
          sub 5 CSW (control store write: cs[X] <- T, the loader
          primitive). Register names 0x20 URX and 0x21 UTX reach the
          console; writing UTX transmits, condition 12 (TXB) is the
          transmitter-busy flag, condition 10 (INT) is receiver-valid.

Rationale for vertical 16-bit encoding: fidelity to the B1700's 16-bit
micros, natural fit to one 18 Kbit BSRAM block at 1024 x 16, and MIL-style
one-statement-one-micro readability. The cost is more micros per
S-instruction than a horizontal format; this is accepted (see performance).

## 5. Field Isolation Unit

S-memory is physically 32-bit BSRAM. A READ presents (FA, length): the FIU
fetches the two adjacent 32-bit words spanning the field, funnel-shifts the
64-bit pair right by FA mod 32, masks to length, and delivers a
right-justified field. WRITE is read-modify-write on the same path.
Direction bit FD implements Wilner's between-bit addressing semantics
(reading k bits forward from a equals reading k bits backward from a+k).
Latency: read 2 cycles, write 3 cycles, pipelined with the next microfetch
where possible.

## 6. RV32I as the first S-language

- S-machine state block in S-memory: x0..x31 (1024 bits), pc (32 bits),
  plus interpreter working cells. x0 is handled by a guarded write path in
  microcode (skip register writeback when rd == 0).
- Fetch: BIAS CPL=32; READ X via F(pc) with count mode "A up": the pc
  advances by 32 as a side effect of the counting read, so instruction
  fetch and pc increment are one micro.
- Decode: EXT opcode (CPL=7, pos 0), DISP into a 128-entry handler page;
  secondary DISP on funct3 where needed.
- Estimated path lengths: ADD 12 to 16 micros, ADDI 10 to 13, LW/SW 14 to
  18, BEQ 12 to 15. At 27 MHz this is roughly 1.5 to 2.5 MIPS. This is a
  design point, not a defect: the machine sells flexibility, as its
  ancestor did.
- Verification: reuse the Kervan cocotb flow; riscv-tests rv32ui suite
  against a golden ISS, plus microcode unit tests in the browser simulator.

## 7. Toolchain and deliverables

- MILce: single-file browser microassembler and micromachine simulator
  (VeriSim-style), share links, VCD export with $dumpfile("dump.vcd").
- UART loader protocol: Gismo-analog boot microcode in initialized control
  store; host-side loader is a web-serial page in the same single-file tool.
- Demonstration goal: load the RV32I interpreter, run a program, then hot
  swap to a second S-language (a small stack machine designed for teaching)
  without resynthesizing the FPGA.

## 8. Measured reality

Verification status: all four RTL modules pass golden-model cocotb unit
suites (fnbox, fiu, useq, b26). The complete RV32I interpreter (ucode
v0.3, 820 microwords, six dispatch pages, six shared microsubroutines)
passes ISS-compared program tests and the official riscv-tests rv32ui
suite, 42/42 including ma_data (misaligned access, supported natively by
the FIU with zero extra microcode).

Corrections to section estimates: FIU read completes in 3 cycles and
write in 4 (synchronous BSRAM latency plus RMW), not 2/3. Measured CPI
is 72 to 77 over the test programs, not the 12 to 16 first estimated;
at 27 MHz this is roughly 360 KIPS. The dominant costs, in order: the
scattered B/J immediate assembly by Horner doubling (about 50 micros per
taken branch or jump), sign extension by xor-subtract (6 micros per use),
and bit-serial variable shifts (4 to 7 micros per bit). Each points at a
cheap micro-ISA extension for v2: a signed EXT variant, a left-shift or
immediate-assembly assist, and a barrel shift step. Control store must be
2 BSRAM blocks (2048 x 16), not 1: the interpreter plus dispatch pages
spans addresses up to 0x9FE.

One micro-ISA lesson worth recording: register file addressing needs no
shifter at all. Extracting the 5-bit register field with 5 junk bits
below it (EXT pos-5, CPL=10) and masking with 0x3E0 yields regnum*32,
the bit address of xN, directly. Defined-field addressing turns what is
normally an address computation into a field extraction.

## 9. Writable control store and the resident loader

The control store is written at run time by CSW, so an interpreter is
data, not a synthesis artifact. Gismo, a 314-microword resident loader
at 0xE00, implements the console and the load protocol entirely in
microcode:

- L addr n, then n 16-bit words: write microcode into the control store
- M word_addr n, then n 32-bit words: write S-memory (counting writes
  advance the descriptor, so the address arithmetic is free)
- G: jump to microaddress 0, starting whatever interpreter was loaded
- ?: reprint the console menu

A halted machine wakes into Gismo on the first received byte, the
modern reading of the B1700 console cassette: the machine at rest is
still addressable from the operator's terminal. Reset enters at 0xE00
and prints the banner; wake enters at 0xE10 and skips it, so binary
loader streams never race the transmitter.

Gismo also exports console services at frozen microaddresses, the
Wilner arrangement in which interpreters call the resident routine
rather than carry their own I/O: SVC_PUTC (0xE05, byte in T), SVC_PUTHEX
(0xE06, S10 as eight hex digits) and SVC_PUTS (0xE07, zero-terminated
string at F.A, read one byte at a time as a defined field). The RV32I
interpreter's ECALL handler prints "a0=XXXXXXXX"; the stack machine's
OUT prints the top of stack. Console text lives in S-memory, not in the
control store.

## 10. Two S-languages on one bitstream

The same GW1NR-9 configuration runs both interpreters, swapped over the
serial line in about a second, with no resynthesis:

| Workload | Microwords | Upload (bytes) | Console output |
| --- | --- | --- | --- |
| RV32I interpreter | 838 | 1810 | a0=000000D2 (sum 1..20) |
| Stack machine | 75 | 179 | 0000000F (7+8) |
| Bare microprogram | 6 | 24 | 0000002A (LIT 42) |

The stack machine is a byte-coded S-language with eight opcodes; push
and pop are single counting FIU accesses through SF, which is Wilner's
one-microinstruction read-and-pop and write-and-push. It costs 9 percent
of the RV32I interpreter's microcode. The third row is the limiting
case: no ISA at all, six microwords loaded straight into the control
store, which is what "the hardware defines no instruction set" means in
practice.

## 11. Synthesis and timing on the Tang Nano 9K

Gowin EDA V1.9.12, GW1NR-LV9QN88PC6/I5, 27 MHz, no PLL.

| Metric | v0.2 core | with console (v0.3) |
| --- | --- | --- |
| Logic cells | 3027 (2528 LUT, 385 ALU, 19 RAM16) | 3070 (2569 LUT, 387 ALU, 19 RAM16) |
| Utilization | 36 percent of 8640 | 36 percent of 8640 |
| Registers | 391 | 461 |
| BSRAM | 12 of 26 (8 SDPB, 4 pROM) | 12 of 26 (12 SDPB) |
| PnR Fmax | 29.710 MHz | to be recorded |
| Worst setup slack | +3.379 ns | to be recorded |

The UART receiver, transmitter, console services and the CSW write port
together cost 41 LUT and 70 registers, about 1.4 percent of the design:
a writable control store and a console are close to free at this scale.
The BSRAM row is the more interesting change. In v0.2 the control store
was read-only and Gowin inferred it as four pROM blocks; adding the
write port turns all twelve blocks into SDPB, which is the synthesis
tool confirming that the machine can now rewrite its own instruction
set.

Both syntheses report a 15-level critical path out of the CPL register,
through mask generation, the 32-bit carry chain, the variable bit select
that produces CYL, the sequencer condition mux and the target adder, and
back to the control store address. That path is not an accident of
coding style: it is the bias mechanism itself, the cost in nanoseconds
of a machine that reshapes its datapath every cycle. Placed and routed,
it fits 27 MHz with margin, and routing rather than logic dominates the
delay, so the next speed step is registering cs_rdata (one bubble on
taken transfers) rather than trimming logic.

## 12. Comparison with fixed-ISA RISC-V cores

Same board, same wrapper (one 4096 x 32 inferred BSRAM, one wait state,
identical reset and LED latch), same 27 MHz constraint, same workload
(sum 1..100 to the LED port, 305 executed instructions):

| Core | LUT | ALU | Regs | BSRAM | Fmax | CPI | Microcode | ISA |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Glacial | 236 | 38 | 108 | 8 | 66.7 | ~953 | in memory, fixed | fixed |
| SERV (WITH_CSR=0) | 283 | 21 | 210 | 9 | 53.9 | 46.6 | none | fixed |
| PicoRV32 (small) | 1097 | 211 | 446 | 10 | 46.3 | 5.0 | none | fixed |
| b2026 | 2569 | 387 | 461 | 12 | 29.7 | 81.3 | in memory, writable | swappable at run time |

Glacial's CPI is an instruction-mix average, not a completed run: using
the core's own instruction-retire trace point, the reference workload
retires 10000 instructions in 9538641 cycles. The program does not
terminate in our harness (the RISC-V PC returns to zero after the fifth
instruction, consistent with a trap taken while mtvec is still zero),
and since Glacial passes the official compliance suite upstream we
attribute this to our environment rather than to the core; the
microcode was assembled locally because the repository ships no
prebuilt image. Its resource numbers come from synthesis and do not
depend on the program.

Read plainly, b2026 loses on every axis a fixed-ISA core is
optimized for: 9 times the logic of SERV, 1.8 times its clock period,
1.7 times its CPI. That is the honest price of the thesis, and it is
worth stating first. What the table does not have a column for is what
the price buys: the hardware implements no instruction set, the control
store is rewritten at run time over the serial line, memory is
bit-addressed so misaligned access costs nothing, and the same
bitstream ran two different S-languages during these measurements.

Glacial deserves separate comment because it is the closest published
relative: also microcoded, also keeping microcode, scratchpad and
program in one memory, and smaller than everything else in the table at
236 LUT and 108 registers. The distance between Glacial and b2026
is therefore not microcoding. It is that Glacial's microcode implements
RV32I and is fixed at synthesis, while here the control store is
rewritten over the serial line and the hardware is committed to no
instruction set at all. A reader who wants a small microcoded RV32I
core should use Glacial; the case for this design is the S-language
layer, defined-field addressing and the writable store, not density.

Two details are worth drawing out. Register counts are close (446 for
PicoRV32 against 461 here) while LUT counts differ by a factor of two
and a half, so the cost of definable structure sits in combinational
logic, not in state: the funnel shifter, the CPL-driven mask generator
and the function box computing all six outputs every cycle. And the
critical path depth (SERV 5 levels, PicoRV32 6, b2026 15) is the
bias mechanism measured in logic levels, the nanosecond cost of a
machine that reshapes itself every cycle.

## 14. Open questions for v0.5

1. Glacial (microcoded, 8-bit datapath) still needs a wrapper for the
   comparison table; it is the closest published relative.
2. Micro-ISA extensions justified by the CPI measurements: a signed EXT
   variant, an immediate-assembly assist, a barrel shift step.
3. Register cs_rdata to lift Fmax, accepting one bubble on taken
   transfers.
4. A second loader region so Gismo itself can be updated over the wire.
5. MILce: single-file browser microassembler and simulator; the Python
   encoders are already its core.
6. Unified memory with an M-cache (microfetch from S-memory), the
   remaining fidelity gap to the original.
7. Project name final decision.
